# Codex开发交接（2026-11-02）

## 首先检查

主程序在 asphalt-timer-4.3c/asphalt-timer-4.3c.ino，发布bin与该源码对应。硬件为ESP32-S3-Touch-LCD-4.3C；Arduino ESP32 3.1.1，16M Flash、OPI PSRAM、原生USB CDC。

用户数据必须保留。不要自动擦除Flash、格式化文件系统或覆盖分区表。应用只写0x10000，最大0x300000。当前分区表：

| 分区 | 起点 | 大小 |
|---|---:|---:|
| nvs | 0x9000 | 0x5000 |
| otadata | 0xe000 | 0x2000 |
| app0 | 0x10000 | 0x300000 |
| app1 | 0x310000 | 0x300000 |
| timer_nvs | 0x610000 | 0x20000 |
| ffat | 0x630000 | 0x9d0000 |

原电脑可靠烧录工具为esptool 5.6.0，原生USB使用usb-reset/watchdog-reset。旧esptool 4.8.1曾出现大块读取错误，不要据此判断备份有效。串口打开可能重启板子，实机交互测试期间保持同一连接，避免反复重开。

## 模块

- step_logic.*：计时规则；跳过已开始步骤时保留原开始时间。
- lab_store.*：LAB3双槽NVS，与旧LAB2迁移兼容；不自动清空损坏记录。
- results.*：数值模型、十进制输入、修约、单位换算和老化比较。原始值是字符串，不可被结果修约覆盖。
- result_store.*：独立结果NVS、校验、无损零字节压缩、读回、TF CSV/JSON、Markdown与手机选择页。
- result_ui.hpp：录入、参数、规范、结果汇总及导出分级界面，包含在主sketch中。
- tf_records.*：TF快照归档，临时写入/读回/替换/上一版本备份。
- transfer.*：Wi-Fi AP、DNS自动登录引导、非阻塞HTTP、共享范围与手机选择项目ID验证。
- pocket_guard.hpp：完整横滑解锁；触摸按亮屏40ms/锁屏20ms独立采样，不能因网络2ms服务循环加速触摸读取。

## 已约定交互

- 底部原有导航不增加按钮。
- 样品内有录入数据、试验记录、结果汇总。
- 导出／传输只在首页“任务”右上角；进入后先日期，再样品，再试验。保留跨日期选择。
- 板子可整日、整样品、单项勾选；也可直接进入“手机上选择”。默认不选任何项目，步骤时间默认不附带，不自动加对照项目。
- 手机按日期、样品、阶段、项目勾选，提交后仅生成选中项目的MD；不能直接把未选择的其他数据夹带进去。
- 列表显示第X/Y页，点页码输入数字跳转，不要让分页控件覆盖试验卡片。
- 规范应提供具体国内/澳洲选项，不能只有“国内规程”占位文字。软化点澳标需明确实际浴液，未选时不输出有效结果。

## 回归要点

数值自检、TF归档和独立NVS重启恢复已经通过。用户确认了热点自动弹页下载、热点期间切回样品及数字跳页。最新的板端三级导出入口尚需完整检查：

1. 任务 → 导出 → 日期 → 样品 → 试验，返回层级正确。
2. 仅勾针入度、软化点时生成文件只含这两项；跨日期选择不丢失。
3. 手机在共享范围内继续细选；空选择、越界ID不能导出。
4. 国内和AS软化点分别验证，AS未选浴液不得出结果；离析不参与普通软化点老化差值。
5. 热点开着时导航、键盘、锁屏手势和提醒继续工作。

串口status、results-test、guard-test、records-test可作诊断。results-test使用独立测试键，不生成用户样品。板内transfer-test连接自身AP曾超时；不要把它当作手机实际无线测试，实际手机HTTP下载已确认成功。不要在诊断脚本中自动切换用户正在看的界面。

当前未实现：BLE接收、手机版可编辑数据库导入、完整BBR独立算法、自动导入TF中已删除的历史项目。通用数值类型不能冒充专用试验算法。
